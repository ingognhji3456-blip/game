# 동작(애니메이션)·그림 개정 설계서

> 사용자 의견(2026-11-09): "몬스터나 캐릭터를 다 붙여서 대충 만든 것 같다. 하나하나씩 그려 달라. 쏘는 모션, 쏘기 전 대기 모션, 활을 당기는 모션, 칼을 휘두르는 모션 등 아주 작은 디테일이라도 있었으면. 캐릭터가 너무 개연성이 떨어져 보인다."
>
> 이 문서는 그 의견을 그림 규칙으로 옮긴 것입니다. 탑·적·영웅·유닛을 **하나씩 다시 그리고**, 상황마다 다른 **자세(프레임)**를 줍니다.

## 1. 지금 그림의 문제 (고칠 것)

| 문제 | 예 | 고칠 방향 |
|---|---|---|
| 부품을 붙여 놓은 느낌 | 팔이 굵은 선 하나, 몸통이 덩어리, 손이 없음 | 어깨→위팔→팔꿈치→아래팔→손, 엉덩이→허벅지→무릎→정강이→발. 관절이 이어짐 |
| 무기가 손에서 떠 있음 | 카라의 망치가 등 뒤에 떠 있음 | 무기는 **손으로 쥔다**(손가락이 자루를 감쌈). 양손 무기는 두 손 |
| 동작이 없음 | 걷기 2장이 거의 같음, 탑은 쏠 때 찌그러지기만 | 걷기 4장, 공격 직전(조준·준비)·공격 순간 자세를 따로 |
| 하는 일과 생김새가 안 맞음(개연성) | 화살이 나가는데 궁수가 활을 당기지 않음 | 공격 방식 = 그림 속 행동. 투사체가 나가는 곳에 실제로 활·포구·수정 끝이 있음 |

## 2. 자세 목록과 고르는 규칙

렌더러(`js/render/renderer.js`의 `towerPose`·`enemyFrame`·`heroPose`)가 시뮬레이션의 타이머를 보고 자세를 고릅니다. 그림 함수는 자세 이름을 받아 그 순간을 그립니다.

### 2.1 탑 — `RG.art.tower(type, level, branch, pose)`

| 자세 | 언제 | 그릴 것 |
|---|---|---|
| `idle` | 쉬는 중 | 조작하는 인물·장치가 편하게 대기(활은 내림, 포는 수평, 수정은 은은함) |
| `aim` | 다음 공격 직전(남은 대기 ≤ 간격의 40%) | **힘을 모으는 순간**: 시위를 끝까지 당김, 포에 불씨, 수정에 빛이 모임, 망치를 높이 듦, 종을 뒤로 젖힘 |
| `fire` | 쏜 직후 0.14초 | **놓는 순간**: 시위가 앞으로 튕김·화살 없음, 포구 섬광과 연기·반동, 수정 섬광, 망치가 내리찍힘·먼지 |

- 빛줄기 탑(햇살 렌즈)은 쏘는 동안 계속 `fire`.
- 공격하지 않는 탑(대장간·축전기·성소·수정 광산·바위 병영)은 **일하는 모습이 반복**됩니다: `idle`(1.7초) → `aim`(0.85초) → `fire`(0.45초). 예: 대장장이가 망치를 들었다(aim) 모루를 내리침(fire), 광부가 곡괭이를 들었다 내리침, 사제가 손을 모았다 빛을 냄, 축전기 코일이 돌며 번쩍임, 병영 깃발이 펄럭이고 문이 열림.
- **같은 탑은 단계가 올라도 같은 인물·장치**가 장비가 좋아지는 식으로 이어집니다(Lv1 궁수 → Lv3 같은 궁수가 갑옷). 분기 A·B는 설명(`towers.md`)대로 서로 다른 역할이 보이게.
- 투사체 출발점 `muzzle`(단계별 5개)은 `aim`/`fire` 자세의 활·포구·수정 끝과 맞춥니다.

### 2.2 적 — `RG.art.enemy(type, frame)`

| 프레임 | 언제 | 그릴 것 |
|---|---|---|
| `walk0`~`walk3` | 걷는 중(걸어온 거리에 맞춰 넘김), 비행 적은 늘 | 한 바퀴: 0 오른발 앞·닿음 → 1 지나감(몸이 살짝 위) → 2 왼발 앞·닿음 → 3 지나감. 네 발 짐승은 대각선 다리 짝, 새·박쥐는 날개 위→가운데→아래→가운데, 슬라임·정령은 눌렸다 늘어남 |
| `aim` | 붙잡혀 싸울 때 휘두르기 직전, 원거리 적이 던지기 직전 | 무기·발톱을 **뒤로 젖혀 들어 올림**, 투석끈을 머리 위로 돌림, 지팡이를 듦 |
| `attack` | 때리는 순간(0.25초), 던지는 순간, 치유·보호막 시전, 보스 능력 | 무기를 **앞으로 내리침**·발톱을 뻗음·물어뜯음, 돌을 놓음, 지팡이 끝 섬광 |

- 걷기 4장 중 `walk0`는 서 있는 자세로도 씁니다(멈췄을 때).
- 그림 함수는 `D.x = (fr) => {...}; D.x.frames = true;` 로 표시하고 프레임 이름(문자열)을 받습니다.
- 공격 방식이 없는 적(비행 적 일부)도 `aim`/`attack`을 그립니다(보스 능력·기본 동작을 과장한 자세) — 같은 그림을 그대로 돌려쓰지 않기.

### 2.3 영웅 — `RG.art.hero(id, pose)`

| 자세 | 언제 | 그릴 것 |
|---|---|---|
| `idle0`·`idle1` | 서 있을 때 0.8초마다 번갈아 | 숨쉬기(어깨·가슴이 1~1.5 올라감), 머리카락·망토 끝 살짝, 무기를 고쳐 쥠 |
| `walk0`~`walk3` | 걸을 때 | 적과 같은 한 바퀴 규칙 + 팔이 다리와 반대로 흔들림 |
| `aim` | 다음 공격 직전 | 카라: 망치를 머리 위로 / 시오: 시위를 끝까지 당김 / 세라: 등불 지팡이를 들어 빛을 모음 / 제나: 배낭 코일과 선으로 이어진 방전 막대를 겨눔(코일이 빛남) / 바위: 주먹(바위 팔)을 뒤로 / 야로: 몸을 낮추고 단검을 거꾸로 쥠 |
| `attack` | 공격 순간 | 망치가 땅을 내리침·불꽃 / 화살을 놓고 시위가 앞으로 / 지팡이 끝에서 빛 / 번개가 장갑에서 튐 / 주먹이 앞으로 / 단검을 그음 |
| `cast` | 기술을 쓸 때 0.5초 | 기술 설명(`heroes.md`)대로 크게: 뛰어올라 내려찍기, 기도, 화살비를 하늘로, 드론 날리기, 땅을 짚어 벽 세우기, 그림자 속 순간이동 |

### 2.4 유닛 — `RG.art.unit(kind, pose)`

`idle` · `walk0`·`walk1` · `aim`(휘두르기 직전) · `attack`. 드론은 `idle`·`aim`(충전)·`attack`(번개), 바위 벽은 `idle`(다른 자세는 `idle`과 같아도 됨).

### 2.5 몬스터별 움직임과 죽음 (추가 요청)

> 사용자 의견(추가): "몬스터들도 다 다시 새로 개편하고, 이동할 때 움직임이며 죽을 때며 다 다르게 해 줘."

- 프레임 `die0`(맞고 휘청·몸이 꺾임) → `die1`(쓰러짐·깨짐·터짐) → `die2`(남은 모습·흩어지기 직전). 렌더러가 죽은 자리에서 차례로 보여 준 뒤 서서히 사라지게 합니다. **몬스터마다 죽는 모습이 달라야 합니다**: 쥐는 뒤집혀 쓰러짐, 허수아비는 짚이 흩어지며 주저앉음, 포자 주머니는 터짐, 녹슨 기사는 갑옷이 무너져 투구가 굴러감, 골렘은 금이 가며 부서짐, 정령은 빛으로 흩어짐, 비행 적은 날개를 접고 떨어짐 등.
- 그림 파일에서 `MOTION[type] = { … }`(`RG.art._en.MOTION`)로 움직임 성격을 정합니다. 렌더러가 그림 전체에 적용합니다.

| 키 | 뜻 | 예 |
|---|---|---|
| `gait` | 이동 방식 이름(설명용) | `walk`·`trot`·`hop`·`slither`·`crawl`·`scuttle`·`stomp`·`roll`·`float`·`fly`·`swim` |
| `bob` | 걸음마다 위아래(칸 단위, 0~0.12) | 쥐 0.03, 멧돼지 0.05, 골렘 0.02 |
| `hop` | 깡충 뛰기 높이(칸, 있으면 bob 대신) | 포자 새끼 0.12 |
| `tilt` | 걸음마다 좌우 기울기(도) | 허수아비 8, 기사 3 |
| `sway` | 좌우 흔들림(칸) | 거머리 0.04 |
| `squash` | 눌렸다 늘어나기(0~0.15) | 슬라임·주머니 0.12 |
| `hover` | 비행 높이(칸, 비행 적만) | 까마귀 0.45, 고래 0.6 |
| `deathFx` | 죽을 때 효과 | `mist`(잿빛 안개) · `shatter`(조각) · `burst`(터짐) · `ash`(재) · `splash`(물) · `spores` · `sparks` · `crumble`(돌가루) · `feathers` |
| `deathTime` | 죽음 연출 길이(초, 0.4~1.2) | 보스 1.2 |

### 2.6 건물다운 탑과 그림자 (추가 요청)

> 사용자 의견(추가): "픽셀을 섬세하게 잡아서 진짜 탑들은 건물같이 하거나, 배치했을 때 이질감이 안 들 정도로 그림자까지 섬세하게 추가해 달라. 사람도 그렇고, 맵도 그냥 이어 붙여 만든 느낌이야. 다 새로 만들어 줘."

- **탑은 건물·구조물**처럼: 기초석과 석재 쌓기(돌 하나하나 모양·줄눈), 목재 들보·널빤지 결, 기와·초가·금속 지붕, 창(안쪽 불빛)·문·계단·난간, 깃발·밧줄·등불 같은 생활의 흔적, 이끼·그을음·녹 같은 낡은 흔적. 장난감처럼 매끈한 원통·원뿔 대신 **짓는 사람이 있었을 법한 구조**.
- **빛은 늘 왼쪽 위**: 모든 그림의 밝은 면·어두운 면·하이라이트가 같은 방향. 돌출부 아래(처마·발코니·창틀 아래)는 짙게(형태 그림자), 땅에 닿는 곳은 가장 어둡게(접지 그늘). 바닥에 떨어지는 **그림자는 그림에 그리지 말 것** — 렌더러가 그림 모양 그대로 오른쪽 아래로 드리운 그림자와 발밑 그늘을 그립니다(그래서 모든 그림이 같은 빛으로 땅에 붙어 보임).
- **사람·몬스터도** 같은 빛 규칙: 몸통의 형태 그림자, 팔이 몸에 드리운 그늘, 옷 주름의 명암.
- **맵**: 칸을 이어 붙인 티가 나지 않게, 길 가장자리는 닳아서 들쭉날쭉, 풀·흙·돌이 서로 스며들고, 건설지는 땅과 어울리는 **기초 터(평평한 돌판·다진 흙)**로, 물가에는 물결·거품·젖은 흙, 절벽에는 높이와 그림자, 나무·바위에도 그림자. 그래도 **어디에 지을 수 있는지, 길이 어디인지는 한눈에** 보여야 합니다.

## 3. 개연성 점검표 (그림마다)

1. **몸 구조**: 머리-목-몸통-골반, 팔은 어깨에서, 다리는 골반에서 나온다. 관절에서 끊기거나 떠 있는 부품이 없다.
2. **쥐는 손**: 무기·도구·지팡이는 손으로 쥔다. 활은 한 손이 활대를, 다른 손이 시위를 잡는다. 양손 무기는 두 손.
3. **하는 일 = 생김새**: 화살 → 궁수와 활, 포탄 → 포와 포수, 마법 → 시전자나 수정, 근접 적 → 무기·발톱·이빨, 원거리 적 → 던질 것. 지원 탑은 무엇을 돕는지 보이게(대장장이, 사제, 코일).
4. **설정 = 생김새**: 영웅은 `heroes.md` 외형(머리색·옷·무기)과 초상화가 같은 인물로 보인다. 적은 `enemies.md`의 외형과 지역 테마(잿빛 몸 + 하얗게 빛나는 눈 + 지역 원소 색)를 지킨다.
5. **땅을 딛음**: 발바닥이 기준선(적·영웅·유닛 y=90, 탑 y=112)에 닿는다. 걷기에서 한쪽 발씩 든다. 비행 적은 기준선 위로 떠도 됨(렌더러가 띄움).
6. **무게와 흐름**: `aim`은 몸이 뒤로 감기고(예비 동작), `attack`은 앞으로 뻗는다. 같은 인물은 모든 자세에서 비율·색·장비가 같다.
7. **작게 줄여도 읽힘**: 게임에서 22~40px로 보입니다. 자세 차이는 **팔·무기 각도 30° 이상**, 시위 당김·섬광처럼 크게. 1px보다 가는 선은 쓰지 않는다.
8. **방향**: 모두 오른쪽을 본다(렌더러가 왼쪽으로 뒤집음). 뒤집어도 어색하지 않게 글자·문장(紋章)은 좌우 대칭이거나 없게.

## 4. 그리는 방법

- 인물마다 **관절 각도 표**(자세 → 어깨·팔꿈치·엉덩이·무릎 각도, 몸통 기울기, 무기 각도)를 두고, 같은 그리기 함수가 표를 읽어 그립니다. 그래야 자세마다 같은 인물로 보이고 동작이 이어집니다.
- 두 마디 팔·다리 도우미(어깨·팔꿈치·손 좌표 → 위팔·아래팔 모양)와 쥔 손 모양을 파일 안에 만들어 씁니다.
- 디테일: 옷 주름 1~2줄, 허리띠·버클, 장갑·부츠 테, 무기의 손잡이 감개, 머리카락 결, 눈동자 방향. 단, 작은 크기에서 지저분해지지 않게 **굵은 외곽선 + 큰 면 + 작은 강조** 원칙(ARCHITECTURE §5.1).
- 기존 viewBox·기준점·외곽선 규칙·원소 색은 그대로(ARCHITECTURE §5).

## 6. 검수

- `node tools/art-review.js <분류> [id]` → `docs/reports/art/<분류>/<id>.png`: 자세마다 큰 그림 + 게임 크기(뒤집기 포함). **모든 자세를 한 장씩 직접 열어 확인**하고 3절 점검표로 판정.
- `RG.art._strict = true`(테스트)에서 모든 자세가 오류 없이 그려져야 하고, 공격하는 대상은 `idle`/`aim`/`fire`(적은 `walk0`/`aim`/`attack`)가 서로 달라야 합니다(`tests/data.test.js`).
- 실제 게임 화면 캡처로 기준점·크기·동작이 읽히는지 다시 확인.
- 결과는 `docs/reports/ART-REVIEW.md` "3차 검수(동작 개정)"에 대상마다 통과/고침으로 기록.
